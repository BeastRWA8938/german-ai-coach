# **ProjektDeutsch AI**

## **AI-Powered German Practice Coach**

**Version:** 2.0 (Architectural Revision)  
**Author:** Rushikesh

# **1\. Problem Statement**

German learners often need topic-specific practice exercises for levels such as A1, A2, B1, and B2. Currently, learners must search multiple websites, find exercises manually, verify answers themselves, and manually track their weaknesses. This process is fragmented and inefficient.  
The goal of ProjektDeutsch AI is to provide unlimited, structured, topic-based German practice exercises powered by advanced LLMs, while tracking learning progress, identifying weak areas, and utilizing a zero-cost infrastructure model leveraging GitHub Student Developer Pack credits.

# **2\. Vision**

Create an AI-powered German Practice Coach that:

* Generates unlimited, contextually accurate grammar exercises.  
* Evaluates answers instantly and explains mistakes.  
* Tracks topic mastery and detects weaknesses without UI performance lag.  
* Encourages spaced revision via a deterministic Confidence Decay algorithm.  
* Operates on a highly scalable, decoupled Python/Next.js architecture with zero baseline operational costs for the platform owner.

# **3\. Target Audience**

**Primary Audience:** Self-learners studying German independently.  
**Secondary Audience:** People preparing to move to Germany, learners preparing for Goethe exams, and students seeking additional grammar practice.

# **4\. Core Value Proposition**

Unlike generic ChatGPT interfaces, ProjektDeutsch AI offers:

* **Structured German Syllabus:** Strict adherence to CEFR levels mapped with thematic vocabulary to prevent unnatural sentence generation.  
* **Progress Tracking & Analytics:** Localized, privacy-first data tracking separating quick dashboard analytics from heavy review logs.  
* **Persistent Learning History:** Weakness analysis and automatic review queues.  
* **Consistent UX:** A seamless app experience prioritizing language acquisition over prompt engineering.

# **5\. Technical Architecture**

The system utilizes a decoupled, enterprise-grade AI architecture to ensure strict data validation and leverage the GitHub Student Developer Pack.

# **6\. MVP Scope**

## **6.1 Secure Freemium-to-BYOK Pipeline**

To reduce onboarding friction for non-technical users while protecting the platform's API quota:

1. **Free Tier:** Users get 3 free exercise generations. The Next.js frontend calls the FastAPI backend, which uses a securely stored master Gemini API key. Free usage is tracked via an encrypted local cookie/IndexedDB.  
2. **The Handshake:** Upon exhausting free credits, the system halts generation and presents a friendly onboarding guide showing the user how to get their own free API key from Google AI Studio.  
3. **BYOK Mode:** The user enters their API key, which is stored locally. Future requests from the frontend pass this key securely to the backend for inference, ensuring zero cost to the platform.

## **6.2 Level & Topic Selection**

* **Levels:** A1, A2, B1, B2  
* **Topics:** Predefined grammar points (e.g., A1 Akkusativ, A2 Wechselpräpositionen).

## **6.3 Thematic Vocabulary Constraints**

To ensure sentences are natural and level-appropriate, the backend utilizes **Thematic Clustering**.

* Instead of random words, the system picks a specific theme (e.g., "A1\_Daily\_Routine") and injects a constrained vocabulary list into the LLM prompt. This prevents the LLM from using B2 vocabulary in an A1 grammar test.

## **6.4 Exercise Format & Evaluation**

* **Format:** Fill-in-the-blank (e.g., "Ich gehe \_\_\_ Schule." \-\> \[\_\_\_\_\_\_\_\_\]).  
* **Instant Evaluation:** Client-side string normalization (lowercase, stripped whitespace) compares user input against the accepted\_answers array. No LLM call required for grading.  
* **Explanation System:** Explains the grammar rule, why the answer is correct, and analyzes common mistakes.

# **7\. Learning Analytics & State Management**

To prevent UI lag as the user's history grows, IndexedDB is split into two optimized tables:  
**Table A: TopicAnalytics (OLTP \- Fast Dashboard Reads)** A flat, lightweight object used to render UI and calculate progress instantly.

* Tracks: Accuracy, Confidence, Attempts, Last Practiced.

**Table B: SessionHistory (OLAP \- Heavy Data Archive)** Stores the raw question/answer arrays.

* Only loaded into memory if the user navigates to a specific "Past Reviews" deep-dive page.

# **8\. Confidence Decay System**

**Purpose:** Encourage spaced repetition without punishing users for taking breaks.

* **Mastery:** Represents historical performance (Accuracy). Does not decay rapidly.  
* **Confidence:** Represents certainty of retention. Decays over time (e.g., 100% on Day 1, 70% on Day 30).  
* **Formula:** Topic Score \= Accuracy × Confidence

# **9\. Dashboard & Review Queue**

* **Level Progress:** The average of all Topic Scores within a CEFR level.  
* **Review Queue:** The system automatically flags topics for review when the Confidence metric drops below a certain threshold or if recent accuracy is poor.

# **10\. Exercise Generation Pipeline**

1. User selects Level & Topic.  
2. Client checks Free Quota vs. BYOK status.  
3. Client requests generation from FastAPI Backend.  
4. FastAPI selects a Random Theme & Vocabulary Cluster.  
5. FastAPI constructs prompt and calls LLM (enforcing JSON output).  
6. LLM responds; FastAPI validates output strictly using Pydantic.  
7. Backend returns clean ExerciseResponse JSON to Client.  
8. User answers questions; Client scores instantly.  
9. Client updates TopicAnalytics and saves raw data to SessionHistory.  
10. Dashboard updates.

# **11\. LLM Data Schema (Pydantic/JSON)**

  "level": "A2",  
  "topic": "Dativ",  
  "questions": \[
